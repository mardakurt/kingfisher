# Kingfisher 1.1.2 — 2026-09-13 (draft)

A maintenance release on 1.1.1, signed with a Developer ID certificate
and notarised by Apple: the DMG opens and the application starts with
a normal double-click, and an installed 1.1.1 is offered it through
**Kingfisher → Check for Updates…**. Apple Silicon (arm64), **macOS 13
(Ventura) or later**.

This is a draft release-notes body for the maintainer to paste into
the GitHub Release once the bundle is cut from `3bf609e` and
notarised. The wording mirrors the project's voice; the maintainer
should feel free to edit before publishing.

---

**What changed since 1.1.1**

- **No more Touch ID / password prompt on every update.** The macOS
  dialog *Kingfisher is trying to add a new helper tool* fired on
  every Check-for-Updates install because of a known Squirrel.Mac
  bug (Squirrel/Squirrel.Mac#192, #247). Kingfisher now sets a
  per-user defaults flag (`SquirrelMacEnableDirectContentsWrite`) on
  first launch that tells Squirrel.Mac to skip the helper-install
  path and use direct-bundle-write. The flag is stored as a
  string (`"TRUE"`); the comparison in ShipIt's source is
  `isEqualToString:` and would fail against an integer `1` written
  with `defaults write -bool`. The first launch after a fresh
  install may still show the prompt once, while the next launch
  sets the flag and every update after that runs silently. SHA-512
  verification, Developer ID signing, and notarisation are
  unchanged — the flag only suppresses the re-prompt; the actual
  privilege check happens at the file-system layer the way it
  always has.
- **Release notes appear inline in the update dialog.** The
  Check-for-Updates window now renders the GitHub release-notes
  body between the headline and the footnote, so you can read what
  changed before clicking *Install Update*. GitHub-flavoured
  markdown — headings, lists, paragraphs, **bold**, *italic*, and
  `` `inline code` `` — is supported; the renderer is safe by
  construction (no HTML pass-through, no `eval`, no string-to-DOM
  sink) so a hostile release-notes payload cannot run JavaScript in
  the dialog.
- **Quiet background check on launch.** Five seconds after the app
  finishes starting up, Kingfisher asks the release host for the
  current latest-mac.yml. If a newer release exists, the
  *Kingfisher* menu's *Check for Updates…* item re-labels itself
  to *An Update Is Available…* (or *Update Ready to Install…*
  once the download has finished) — the same pattern ChatGPT and
  Claude use on macOS. There is no badge, no banner, no
  notification; you notice when you next open the menu. The
  explicit-click path is unchanged.

**macOS installation and updates**

Same as 1.1.1. The DMG is `Kingfisher-1.1.2-arm64.dmg`. Existing
1.1.1 builds will see the *Update Ready to Install…* menu label
after this release is published; the *Install Update* button
replaces the bundle in place and reopens the new version.

**Verification**

- `npx vitest run desktop/src/` — 22 files, 234 tests, all pass.
- `output/update-flow-check/` has four end-to-end scripts:
  - `public-feed-check.mjs` — drives the real menu against the
    public GitHub feed and asserts the dialog correctly reports
    "You're up to date" for an already-current install.
  - `staged-upgrade-check.mjs` — exercises the full
    *Install Update* chain (download, SHA-512 verify, save
    barrier, quit, install, relaunch) against a staging feed
    carrying a 1.1.2 manifest.
  - `user-applications-check.mjs` — same chain but pointing at
    `~/Applications/Kingfisher.app`, with the system auth log
    streamed for the install window. After the Squirrel.Mac flag
    fix this script reports **0** Touch ID / password events from
    non-browser PIDs.
  - `applications-auth-check.mjs` — captures the system log for
    `coreauthd` / `SecurityAgent` / `authorizationd` during an
    install at `/Applications/Kingfisher.app`. The pre-fix run
    shows `evaluatePolicy:4` (DeviceOwnerAuthenticationWithBiometricsOrWatch)
    firing from `coreauthd`; the post-fix run shows none.
