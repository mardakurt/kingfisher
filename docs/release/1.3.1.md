Released 2026-09-26, the same day as 1.3.0, because the Part E run on the
published 1.3.0 found a count that was not true. The web application has the
same source and ships the same code.

Apple Silicon (arm64), **macOS 13 (Ventura) or later**. Signed with a
Developer ID certificate and notarised by Apple, ticket stapled to the disk
image and the application.

## What changed since 1.3.0

The user-facing list is the 1.3.1 entry in
[`CHANGELOG.md`](../../CHANGELOG.md#131--2026-09-26):

- **A move search over a large database said how many games it had
  received, not how many contain the pattern.** Over the 1,048,440-game
  Lichess collection the Library said "5,000 of 1,048,440 games read contain
  it" for opposite-coloured bishops, which 163,840 contain. The companion
  counts every hit and sends the first 5,000; the Library now says both.
- **Preparation reads the companion's databases.** Preparing against a
  player searches every database the companion holds — a Lichess month you
  imported, your own ChessBase file — each as its own source with its own
  count, never merged with the others.

Nothing under `desktop/` changed.

## Installing and updating

Download `Kingfisher-1.3.1-arm64.dmg`, open it, drag Kingfisher to
Applications, and double-click. An installed 1.1.8–1.3.0 is offered 1.3.1
through Sparkle's own window (_Kingfisher → Check for Updates…_); an
installed 1.1.0–1.1.7 is offered it by the engine those versions shipped
with. The work in `~/Library/Application Support/kingfisher-desktop/` is not
touched by the update.

## Verification

The exact bytes the landing offers are in `src/release/macos-download.json`;
`npm run desktop:public:verify -- --landing --full` downloads and checks
them. The commands run for this release and their results are in
