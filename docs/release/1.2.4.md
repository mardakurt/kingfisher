# Kingfisher 1.2.4

Released 2026-09-20. The whole-codebase audit after 1.2.3 and the five
improvements built on it: a pasted position is the same position as a
played one, route actions fold to fit, PGN from the current move, the
engine's score by depth, "Known position?" in Set up, and one-click drills
of a repertoire's coverage gaps. The web application has the same source
and ships the same code.

## What changed since 1.2.3

The user-facing list is the 1.2.4 entry in
[`CHANGELOG.md`](../../CHANGELOG.md#124--2026-09-20). In two paragraphs:

Sixteen defects from the audit. The one a player would meet first: a
position that arrived through a `[FEN]` tag, the Set up dialog or a link
carried a different identity from the same position reached by playing the
moves (the en passant field), so the explorer, the repertoire and the "in
your work" counts each saw half the evidence; every position now enters
through one canonical form. Also: an engine switched while another was
still starting no longer runs the first under the second's name; the
Lichess "Min Elo" filter asks for the band you typed; the "also reached
by" move orders stop at the arrival; a FEN with nine squares on a rank is
refused; arrows on the starting position survive a PGN export; counts of
one read as one; header titles stay readable; a tab left open across an
update says to reload.

Five additions. Every workspace header folds its route actions into a "⋯"
menu rather than squeezing its title. "Copy PGN from this move" (Export
menu, a move's context menu, the command palette) writes the game from the
current move on as its own PGN. The engine panel draws the top line's score
at every depth with the top-move changes marked. Set up says where the
position being built already is — your games, chapters, repertoire,
training — and how many games the reference has. The repertoire's coverage
panel offers the built-in Starter pack and "Train these gaps", which opens
Training on a set named for the repertoire.

Nothing under `desktop/` changed; the Sparkle feed, the notarisation
pipeline and the release machinery are as in 1.2.3.

## Installing and updating

Same as 1.2.3: download `Kingfisher-1.2.4-arm64.dmg`, open it, drag
Kingfisher to Applications, double-click. An installed 1.1.8–1.2.3 is
offered 1.2.4 through Sparkle's own window (_Kingfisher → Check for
Updates…_); an installed 1.1.0–1.1.7 is offered it by the engine those
shipped with (the release carries `latest-mac.yml` for it).

## Verification

The exact bytes the landing offers — size, SHA-256, build number and
commit — are in `src/release/macos-download.json`; `npm run
desktop:public:verify -- --landing --full` downloads them from GitHub
and checks the hash, the signature and the stapled ticket. The
commands run for this release and their results are recorded in
[`docs/reports/phase-73-handover.md`](../reports/phase-73-handover.md).
