# Kingfisher 1.2.0

Released 2026-09-17. The board is full-size again, the Training icon
reads as a chess knight, and the Mac application picks up every
change shipped to the web between 1.1.9 and today in a single
release. The web application has the same source and ships the
same code.

Apple Silicon (arm64), **macOS 13 (Ventura) or later** — the floor of the
Electron 44 runtime the application is built on. Signed with a Developer ID
certificate and notarised by Apple, ticket stapled to the disk image and the
application.

## What changed since 1.1.9

The user-facing list is the 1.2.0 entry in
[`CHANGELOG.md`](../../CHANGELOG.md#120--2026-09-17). In one paragraph:

The board had a chain of layout regressions across five phases that
together collapsed it to a 24 × 24 px square. The toolbar row that
hosted the Analyse button above the board (Phase 62) created the
chain — its height ate into the eval bar's column assignment (Phase
65), and the grid's `1fr` row, with no definite height, collapsed to
zero (Phase 66). Phase 67 removes the toolbar entirely; the engine
panel's own Analyse button is the single source of truth for
starting an analysis, and the board fills its grid. The Training
icon (the `Recall` icon in the sidebar) is redrawn as the chess
knight every chess set draws — a base, a chest that curves into a
neck, a forehead that slopes up to an ear, and a muzzle that points
right under a clear eye. The layout math lives in
`board-grid.ts` and is pinned by 13 unit tests; the icon is pinned by
four. The full chain, the rules that came out of it, and the failures
that produced them are recorded in
[`docs/product/postmortem-board-tiny.md`](../product/postmortem-board-tiny.md)
so the next agent who adds a row above the board reads it first.

The Mac shell picks up the title-bar brand-inset fix from Phase 64
(`kingfisherchess.app`'s fullscreen now reads from the same 14 px
design inset as the web layout) and every web change in between. The
Sparkle feed, the notarisation pipeline, the relaunch-profile file,
and the existing release machinery are unchanged.

## Installing and updating

Same as 1.1.9: download `Kingfisher-1.2.0-arm64.dmg`, open it, drag
Kingfisher to Applications, double-click. An installed 1.1.0–1.1.9
is offered 1.2.0 by the engine those shipped with (the release
carries `latest-mac.yml` for it); an installed 1.0.x gets 1.2.0
through the Sparkle window.

## Verification

The exact bytes the landing offers — size, SHA-256, build number and
commit — are in `src/release/macos-download.json`; `npm run
desktop:public:verify -- --landing --full` downloads them from GitHub
and checks the hash, the signature and the stapled ticket. The
commands run for this release and their results are recorded in
[`docs/reports/phase-68-handover.md`](../reports/phase-68-handover.md).
