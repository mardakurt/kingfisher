# Kingfisher 1.2.6

Released 2026-09-20. The Team hub reaches the Mac application, together
with the second pass that made it a daily tool and the preparation loop a
coach or a second actually runs: a searchable inbox with a review queue,
suggested briefs, the latest board one click away, and note drafts that
survive a failed save. The reset control's label now says where the board
goes. The web application has the same source and ships the same code.

## What changed since 1.2.5

The user-facing list is the 1.2.6 entry in
[`CHANGELOG.md`](../../CHANGELOG.md#126--2026-09-20). In one paragraph:

**Team** (`/team`) is a new section in the rail. A coach and their
students, or a player and their seconds, hand work to each other on the
one board: an assignment carries a brief and a due date; a hand-in
carries the board as PGN, replayed through Kingfisher's rules before it is
stored, with an evidence line saying which engine looked at how many
positions at what depth — or that none did; a review returns it accepted or
with a correction. The team travels as a packet file — no server, no
account — and threads merge by adding, so a packet received twice changes
nothing. The rail is an inbox: search by title, opponent or brief; filter by
member; choose _To review_ or _Assigned to me_; earliest due first. _Use
suggested brief_ inserts an editable starter for each kind of assignment
— think first, check with the engine, say what changed. _Open latest
board_ reaches the newest board in a thread. A note draft stays with its
assignment while you read another, carries no board unless you are handing
in, and is kept when a save fails. The board's reset control is now _Clear
the move tree — back to the starting position_, which is what it does.

The packet is the whole team, filters included — the rail says so. Separate
teams are the boundary for confidential preparation until an export with
an explicit audience exists; the design and the sources are in
`docs/design/team-hub.md` and `docs/design/team-preparation.md`.

Two new IndexedDB stores (schema v18) hold teams and assignments; both are
in the portable backup. Nothing under `desktop/` changed; the Sparkle feed,
the notarisation pipeline and the release machinery are as in 1.2.5.

## Installing and updating

Same as 1.2.5: download `Kingfisher-1.2.6-arm64.dmg`, open it, drag
Kingfisher to Applications, double-click. An installed 1.1.8–1.2.5 is
offered 1.2.6 through Sparkle's own window (_Kingfisher → Check for
Updates…_); an installed 1.1.0–1.1.7 is offered it by the engine those
shipped with (the release carries `latest-mac.yml` for it).

## Verification

The exact bytes the landing offers — size, SHA-256, build number and
commit — are in `src/release/macos-download.json`; `npm run
desktop:public:verify -- --landing --full` downloads them from GitHub
and checks the hash, the signature and the stapled ticket. The
commands run for this release and their results are recorded in
[`docs/reports/phase-74-handover.md`](../reports/phase-74-handover.md).
