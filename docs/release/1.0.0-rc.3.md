# Kingfisher 1.0.0-rc.3

A chess research workstation for players who study. The third release
candidate, and the first one prepared for people who are not the person who
built it: the notes below say exactly what has been run, and — more usefully —
exactly what has not.

**What changed since rc.2.**

**The macOS title bar looks composed rather than merely uncollided.** rc.2
stopped the window buttons being drawn on top of the Kingfisher mark. It did
not make the corner look intentional, and the difference is measurable: the
mark sat 32 px clear of the last button where the design said 16, the buttons
rode eight pixels high against the row they belong to, and the brand group ran
nine pixels past the sidebar header's own right inset. All three are now stated
as geometry in one place and asserted by the harness, which grew from 51 checks
to 107.

**Three of the four reference sources cannot be installed, and Kingfisher now
says so honestly.** Elite OTB, Recent Theory and High-Rated Online all point at
a publishing address that returns 404 — the data repository behind it has never
been created. rc.2's notes described them as "optional, one click each", which
was not true. What a person pressing Install was told was worse: "The pack
description could not be downloaded (HTTP 404). Check your connection and try
again." Their connection was fine, and no retry could ever have worked. See
**Reference data** below for exactly where this stands.

**Support information you can send.** A short eight-line summary for a chat or
the top of an issue, the full report to attach to it, the address every
reference source was fetched from, the actual operating system and architecture
rather than a frozen user-agent string, and — on the desktop — a bounded local
log that survives a quit, so "it would not start" is answerable.

## What Kingfisher is

One place to do the work that is currently spread across a database program, a
browser tab, an engine GUI and a folder of PGNs:

- **Analysis** with a real move tree — variations, annotations, comments, and
  evaluations attached to the position they were made in.
- **Opening research** across several sources at once, each kept separate, each
  labelled with where its numbers came from.
- **A Theory Book** of named openings and their branches, which shows no counts
  and no evaluations, because a name is the only claim it is entitled to make.
- **A repertoire** of what you intend to play, with spaced review.
- **Preparation** against a specific opponent, from their own games.
- **Game review** — your decisions, judged by an engine pass, with a journal.
- **A game database** that scales from a handful of PGNs to millions of
  positions, with structural and strategic search.

It is **local-first**. Your games, studies, notes and repertoire live on your
machine, and everything above works with the network switched off.

## Requirements

**Web.** A current Chromium, Firefox or Safari. For the multi-threaded engine,
a cross-origin-isolated context; without one Kingfisher uses the
single-threaded build and says so. Storage is IndexedDB.

**macOS desktop.** macOS 11 or later, Apple Silicon. It bundles everything it
needs — there is no separate companion to start, no terminal, no Node, no
SQLite to install.

---

## macOS status — read this before expecting to install it

The application is built, code-signed with the hardened runtime, and driven end
to end. **It is not yet notarised, so Gatekeeper will refuse to open it**, and
that is not something a user can work around safely.

Notarised distribution needs an Apple **Developer ID Application** certificate.
The signing identity available to this build is an _Apple Development_
certificate, which is for running on registered devices, and an _Apple
Distribution_ one, which is for the App Store. Neither is the right kind. The
rc.3 build log says `skipped macOS notarization` for that reason and no other.

**What this means practically.** The macOS product is finished; the ability to
hand somebody the installer is not. Everything needed for notarisation —
entitlements, hardened runtime, the signing and stapling steps — is configured
and committed, and it is a single credential away.

**Windows and Linux** are configured and build, and are **not** supported
releases: see Known limitations.

## Reference data — the one thing to know before you start

Kingfisher ships with **Kingfisher Starter**, and it is genuinely enough to
work with: it installs itself on first run, works offline, and answers twenty
full moves deep. Nothing below affects it.

Three larger sources are listed in the catalog — **Elite OTB** (407,538 games,
5.4 million positions), **Recent Theory** (44,200 games) and **High-Rated
Online** (305,169 games). All three are **built and verified but not
published**. Their Install buttons fail, because the address they point at
answers 404:

```
$ curl -s -o /dev/null -w '%{http_code}\n' \
    https://mardakurt.github.io/kingfisher-data/reference-elite-v2/manifest.json
404
```

This is a publishing task, not a defect in the software: the install path is
certified end to end against a real 33.9 MB, 80-chunk pack, including a
corrupted chunk that correctly refuses to become a source. `docs/data/reference-packs.md`
has the full matrix.

Until they are published, a source is still installable from any address that
serves a Kingfisher manifest — Databases → Reference sources → **Install from a
URL** — which is the same verified code path.

## Engines

Stockfish 18 runs in the browser everywhere. On the desktop, native engines are
downloaded from each project's own release page, checked against a recorded
SHA-256, and made to complete a real UCI handshake _and_ a real search before
they are listed as ready.

They are **not sandboxed**, and Kingfisher does not claim they are. A managed
native engine is a program running with your user account's permissions, like
any other application you launch. The interface says so beside each one, along
with exactly what is and is not checked.

## Privacy

- **No telemetry.** Nothing is collected, and there is no analytics endpoint.
- **No upload.** Your games, studies, notes and repertoire never leave your
  machine unless you export them yourself.
- **The desktop log stays on your machine.** Kingfisher writes launch,
  companion and quit events to a bounded local file so that a start-up failure
  can be diagnosed. Nothing sends it anywhere; Diagnostics reveals it in the
  Finder and you decide what to do with it.
- **Network only where you asked for it.** Lichess and Chess.com are contacted
  only when you connect them or query a source that is theirs. Engine and
  reference-pack downloads go to the URLs recorded in the catalogue.
- **Tokens are never logged**, and both the support summary and the full report
  say whether a credential is configured, never what it is.
- **Local paths stay local.** A file path chosen on your machine is not sent to
  any remote service.

## Sending a bug report

Settings → Diagnostics → **Copy support information** gives eight lines to
paste at the top of an issue: version, machine, web or desktop, which sources
are ready, which engines started, the companion, storage.

**Copy full diagnostic report** is what to attach to it. It adds the address
every reference source was fetched from, storage counts, an integrity scan,
provider health and any component failure this session. Neither contains games,
studies, notes, tokens or keys.

On the desktop, **Show log in Finder** reveals the shell's own log — launch,
companion failures and quit, bounded to about a megabyte. It is the right thing
to attach when Kingfisher did not get as far as a window.

A useful report is four sentences: what you were doing, what happened, what you
expected, and the support information.

## Known limitations

These are real and stated rather than discovered:

1. **The macOS application is not notarised**, so it cannot be installed by
   somebody who was simply handed it. See above.
2. **The three optional reference packs are not published.** See above. This is
   the largest practical limitation for a new user who wants more data than
   Starter holds.
3. **No auto-update.** Updating means downloading the new build.
4. **Windows and Linux are unsupported.** Packaging is configured and produces
   artifacts; installation and launch have not been validated on either, so
   they are not offered as releases.
5. **macOS Intel builds but has not been launched.** Build verified, runtime
   unverified.
6. **No games before 2020.**
7. **Chess960 is not supported**, deliberately. Kingfisher refuses positions it
   cannot play rather than guessing at them.
8. **The engine comparison takes two engines**, by decision. Three readings
   produce a majority, and a majority is a verdict wearing the costume of
   evidence.
9. **Local Syzygy tablebases need tables you supply.** On the macOS
   application the probe helper (MIT-licensed Fathom) ships inside the bundle,
   so there is nothing to compile: point Kingfisher at a folder of Syzygy files
   with Browse… in Settings. On the web the helper is built on your own machine
   with `npm run tablebase:install`. Without either, endgame answers come from
   the public Lichess service, and the board says which answered.
10. **Historical master games can be opened but not saved locally**, pending a
    clear answer on the provider's redistribution terms.
11. **Sleep and wake are verified by analogue, not by sleeping a Mac.**
    `npm run desktop:suspend` stops every Kingfisher process for twenty seconds
    and resumes them, which reproduces the timer and deadline behaviour of a
    sleep but not the network interface coming back or the GPU process being
    re-created.
12. **There is no photograph of the macOS window buttons in this repository.**
    Screen-recording permission is denied to Electron on the build machine —
    `systemPreferences.getMediaAccessStatus('screen')` returns `denied` — so the
    corner is evidenced by measured geometry from both processes instead.

## Licences and provenance

Every third-party dataset, asset and engine is recorded with its source and
licence:

- [`THIRD_PARTY_DATA.md`](../../THIRD_PARTY_DATA.md) — games, positions,
  players, opening names
- [`THIRD_PARTY_ASSETS.md`](../../THIRD_PARTY_ASSETS.md) — boards and pieces
- [`docs/ENGINES.md`](../ENGINES.md) — every engine, its licence and its source

Opening names come from the CC0 lichess-org classification dataset. Reference
packs are built from the Lichess open database. Kingfisher does not invent
opening names past what the source classifies: a deep position inherits the
last named opening above it rather than acquiring a new one.

**Where a number came from is never lost.** Sources are never silently merged,
and comparing two populations puts each in its own column with its own game
count and licence. There is deliberately no combined figure — elite
over-the-board play and 2400+ blitz disagree, and the disagreement is the
reason to look at both.
