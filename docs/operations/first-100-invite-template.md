# First-100 — Invite template

A short message the maintainer can paste into a chat or an
email to invite someone to Wave 1.

The point is to be short, honest, and to leave the user free
to use Kingfisher however they want.

## The template

```
Hi [name],

I am running a small beta of Kingfisher, a chess research
workspace I have been building for a while. There is no
account, no install, and no catch — open it here:

    <canonical landing URL>

Use it for real chess work this week: analyse a game,
search a position, build a study, train a line, whatever
you would normally do.

If something breaks, or feels confusing, slow or wrong,
the fastest path is Cmd+K inside the application and
"Report a problem". Settings also has a "Help and
feedback" section with the same links.

There is no survey, no interview and no obligation. Just
use it normally and tell me what you find.

Thanks,
<maintainer>
```

## What is deliberately NOT in this template

- a feature list (the user should discover the surface, not be
  briefed on it);
- a request to "test" specific features (that turns a real
  cohort into a script);
- an apology for rough edges (the maintainer owns those, but
  the user does not need to be told to expect them);
- a marketing sentence (the maintainer is recruiting real
  users, not selling a product);
- a request for a testimonial or rating (the project does not
  collect those);
- a link to a survey (no analytics, no telemetry, no dashboard).

## What IS in the template

- one URL, no others;
- one command, "Report a problem";
- one location, "Help and feedback";
- one expectation, "use it for real chess work";
- one ask, "tell me what you find".

That is the entire cohort onboarding. The maintainer is the
only audience for the rest of the docs.
