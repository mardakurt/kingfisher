## Actual user workflows and regression proof

The video test recorded a synthetic colour card solely as a media fixture.
Chrome decoded and played it, moved the canonical board at timed cues, sought
backwards, allowed free exploration and resumed following. Reload preserved
filename and cues without preserving video bytes. A mismatched file was
refused. Removing and clearing cues worked. Switching chapters immediately
after editing retained work and detached the media. Layouts at 1440 × 900,
1280 × 720 and 390 × 844 and dark theme were inspected; phone controls require
vertical scrolling through the existing stacked workspace.

Synthetic tagged and untagged PGN fixtures were imported into the actual browser repository and
an actual SQLite companion. Annotator, source and either team's tags filtered
correctly; the same words in a comment did not match. A saved metadata query
survived reload, ran against the imported games and restored all three fields
into the search mask. The Explorer displayed
actual distinct-game player frequencies from imported games. PGN and portable
backup/restore carried cues through the real implementations.

Each of these deliberate mutations failed its regression and was restored:

- Omit video cues from PGN serialization.
- Drop the annotator tag filter.
- Count duplicate game postings more than once.
- Credit strongest players without verifying the starting position.
- Remove the study navigation save barrier (real browser regression).
- Treat all recovery trees as equal (unit and actual cue-only immediate reload).
- Restore the unsupported browser prompt instead of the naming dialog.

The first full browser run was interrupted during layout tests after review
found the recovery comparison gap. It is not counted as a passing gate.
The second recorded 321 passed checks and was interrupted during the next check when an actual 1.4.4 packaged
Save query probe failed with `prompt() is not supported`, no dialog and no
saved query. That isolated-profile probe is recorded in
`/tmp/kingfisher-145-prompt-probe.log`; browser prompt acceptance had hidden
the platform defect. The shared naming dialog replaces it. Targeted saved-query,
metadata and Phase 7 workflows passed **9/9** after the change.

A preliminary development package at `/tmp/kingfisher-145-qa/` (1.4.5,
build 1074, dirty source, Developer ID signed, not notarized) passed the actual
Mac workflows: decoded video playback, cue seeking, independent exploration,
immediate reload, fast chapter switching, saved metadata query creation and
reload, restored filters, exact player frequencies and import/filter through
the managed SQLite companion. Zero renderer page errors. This is feature
proof, not stable release certification; the final package must repeat it.
Evidence: `/tmp/kingfisher-145-qa-dist.log`, `qa-user.log`, and
`packaged-*.png`, all with the `/tmp/kingfisher-145-` prefix.

## Completion (second session, 2026-10-03 evening)

The first session stopped with certification running, one unexplained
visual failure and 1.4.5 still a draft. Everything below was run against
`/tmp/kingfisher-release-1.4.5-1077/mac-arm64/Kingfisher.app` (1.4.5,
build 1077, `ef00408`, stable, clean), the bytes uploaded to the draft.

**Two inherited failures, explained and fixed (`e75548a`).**

- _The visual failure_ was 26,104 differing pixels, 2.01% against a 2.00%
  tolerance; the isolated rerun passed at just under it. The darwin baselines
  dated from 26 September and predated Puzzles, ⌘K search, New folder and the
  Phase 87 Lichess buttons, so every page sat near the threshold against a
  picture of an older application. All 23 were redrawn and looked at; the
  visual spec then passed 43/43 in compare mode.
- _Certify's walk failed_ "no main window came back" after `close-and-reopen`
  closed a full-screen window and slept a fixed 400 ms. The harness now waits
  for the close (a finding after 10 s) and accepts any loopback route rather
  than twelve named ones. The slow close was **not reproduced** on a quiet
  machine (100 ms); the diagnosis is reasoned from the shell log's timing.

**A third defect found while verifying the draft (`SHA256SUMS`).** Every
release's `SHA256SUMS` carried a byte-count column, so the runbook's
`shasum -a 256 -c SHA256SUMS` failed for every file. Fixed in the publish
script; the 1.4.5 draft's file was replaced before publication (0 downloads)
and checks OK after download.

## Release validation findings

The first live hosted video check failed because Vercel's separate CSP
omitted `media-src`. Commit `c35c641` allows local blob media at the edge,
matching the application policy. Removing that directive failed the new
documentation assertion. The final isolated production user check passed
video playback, cue navigation, immediate reload, chapter switching, phone
and laptop layouts, dark mode selected through Settings, saved metadata
queries and player frequencies, with zero page errors. A separate intervening
run stopped on the validation script's assumption that a preferences record
already existed; the script was corrected to use the actual Settings control.

The first stable candidate, build 1075 from `e1c3b70`, was signed and its
application notarized and booted. Its DMG submission was **rejected** by Apple
(job `1e9123dd-2a83-485f-a2a4-53d772a0ba90`): the signature was invalid.
Inspection found Next.js 16.3.8 promoted prerendered pages into
`.next/server/route-cache` inside the sealed application at runtime.
The boot test therefore changed signed resources before the archives were made.
This candidate has not been published. Desktop builds now disable ISR disk
writes while retaining memory caching; hosted builds retain their defaults.
The after-sign boot gate checks the complete code signature after closing the
application. It rejects the affected candidate in a real packaged regression.
A replacement stable build must pass this gate and all acceptance checks.
